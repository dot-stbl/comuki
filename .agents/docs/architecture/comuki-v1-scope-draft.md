## Task Sources / Intake

**Обещание:** задача попадает в Comuki извне или изнутри через один
внутренний контракт (`IncomingTicket`).

### Провайдеры (все в v1.0)

| Provider | |
|----------|--|
| Native (UI / API Comuki) | |
| GitHub Issues | |
| GitLab Issues | |
| Yandex Tracker | |
| Jira | |
| Chat harness | см. ниже — тоже источник + больше |

Адаптер на провайдер; оркестратор провайдеров не знает.

### Admission (оба режима обязательны)

| Режим | Поведение |
|-------|-----------|
| **Watch + filter** | Как AppSet: смотрит источник, матч фильтра → берёт в работу |
| **Catalog + «взять в работу»** | Список из провайдера в UI; человек жмёт → run |

### Sync

Двусторонний: статусы Comuki run → обратно в трекер (+ комментарий со
ссылкой на run).

### Identity

**Одна задача = один run.** Ключ `(source, externalId)`; не плодим
параллельные активные run на один issue.

## Chat Harness

**Роль:** харнес Comuki для **разговора с мозгом** + быстрые действия
по платформе. Не inbox-only.

### Scope (черновик)

- Обсудить задачу / идею / run
- Запустить в работу из чата
- Mid-run: увидеть проблему → поправить через оркестратор
- Читать PR comments (git-provider)

### Mid-run рычаги (безопасно)

| Действие | Механика |
|----------|----------|
| InjectContext | Докинуть замечание в бриф/сессию (Translator) |
| Stop + rebrief | Новый контейнер с фидбеком |
| Escalate | На ведущую / человеку |
| Nudge verify | Перепроверка |

Запрещено: произвольный shell в живом воркере, обход оркестратора.

PR: **read** обязателен; **write** в PR — opt-in / за апрувом (TBD).

### Архитектура

```
Человек ↔ Chat Harness (Voluta graph)
              │ typed intents / tools
              ├─► Мозг (ведущая модель)
              └─► Оркестратор API (create/status/stop/…)
```

| Кто | Отвечает | Не отвечает |
|-----|----------|-------------|
| Chat (Voluta) | Сессия, clarify, HITL | DAG, lease, proxy, verify |
| Мозг | Смысл (план/ответ) | Durable / исполнение |
| Оркестратор | Факт (run, статусы) | Болтовня |
| Dashboard | Тяжёлый ops (diff, cost, trace) | Быстрый clarify |

Где живёт сервис (отдельный host vs модуль) — **не зафиксировано**
(вопрос ушёл в mid-run/PR до ответа).

## Харнесы (рантаймы)

| Роль | Выбор |
|------|--------|
| Воркер в контейнере | **pi** + `comuki-worker-sdk` |
| Разраб локально | Claude Code + `comuki-dev-sdk` |
| Chat ↔ мозг | **Voluta** (свой граф) + tools = platform API |
| Мозг (план/бриф/вердикт/ремонт) | Typed API calls + schema-валидация из оркестратора — **не** полный agent-loop |
| Hermes Agent (Nous) | **Не берём как рантайм**; идеи (траектории, skill-from-task) — в eval/control-plane |

### Project learning loop (не user-memory)

Сигналы: частые PR comments, verify fails, human reject  
→ кандидат правило / скилл / analyzer-check  
→ человек апрувит → git-rev control-plane  
→ принуждение **кодом** (нивелирует галлюцинации и раздутый контекст).

Детали порогов/агрегации — отдельное обсуждение.

Согласуется с P7: человек замыкает петлю; авто-самоизменения рантайма нет.

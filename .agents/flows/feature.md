# feature

Продуктовая задача в comuki. Человек называет, что сделать, и шаги не диктует. Код начинается только после OpenSpec.

## Шаги

1. **grill** — мастер сам (скилл grilling). Не Task. Один вопрос за раз, у каждого вопроса есть рекомендуемый ответ. Факты из репозитория смотри сам, решения спрашивай. Кончай, когда человек подтвердил общее понимание. Без этого подтверждения шаг 2 не начинай.
2. **code**, скилл openspec-propose — по подтверждённому пониманию заводит openspec/changes/<kebab>/: proposal.md, design.md, tasks.md, дельта-спеки. Код продукта не трогает. В конце openspec validate. Имя change — в итоге шага.
3. **Человек** — читает change. Дальше только после «погнали» или правки словами. Молчание — не согласие.
4. **explore** — где жить правке: platform/, dashboard/, agents/, cli/, control-plane/. Только чтение. Сверяется с design.md, не расширяет его.
5. **code**, скилл openspec-apply-change — пункты tasks.md по порядку. Тесты рядом с кодом, где они уже приняты. Гейт после кода. C#: `dotnet build comuki.slnx -c Debug`. dashboard/: из dashboard/ команды `bun run typecheck` и `bun run test`.
6. **review** + **reinvention** — оба не правят код. Шаг 6 закрывается, когда вернулись оба.
7. **code** — только blocker и major из шага 6, плюс замены из reinvention. design.md не переписывает. Потом шаг 6 ещё раз. Кругов правки не больше двух.
8. **Человек** — черновик PR по `.agents/rules/process/commit-and-pr.md`: что сделано, зачем, как проверено. Коммит (subject + тело, если из subject не ясно зачем) и PR — только если в задаче было «закоммить» или «открой PR».

# Phase 6 — Slice 3: Verification Gate & Rules

## Цель

Гейт верификации отказывается пропускать работу, которая не прошла
детерминированные проверки. Жёсткие правила принуждаются хуками / extensions,
а не уговорами. Anti-slop hardening: hooks, не vibes.

Подробное обоснование — `.agents/docs/architecture/comuki-architecture.md` § 03, § 06 и
`.agents/docs/architecture/comuki-decisions.md` § "Верификация — несущая стена".

## Что входит

Заполняется в `soly plan 6`. Ожидаемый scope:

- Verification stage: типы / lint / unit / build. Roslyn `warnings-as-errors`
  из Phase 1 — несущая опора, не придирка.
- `Comuki.Platform.Rules` — движок правил: scope (global / app / stage /
  task-type), версионирование, детект конфликтов.
- `comuki-worker-sdk` (TS, доля в `agents/`) — pi-extensions, блокирующие
  правку тест-файлов, install, push в main.
- `comuki-dev-sdk` (TS) — Claude Code hooks с тем же набором запретов для
  разрабов в IDE.
- Политика эскалации: N фейлов на дешёвой модели → переключение на ведущую.
  Явный kill-switch.
- Budget caps: per-task, per-app, global.
- Метрика "cost-per-successful-task" (не "cost-per-call") — лечит риск
  "дешёвые ретраи могут стоить дороже дорогой модели" (architecture.md §08).
- Один свод правил — проектный (в репо продукта, для воркера + разраба) +
  второй — воркер (в `control-plane/`, появится в Phase 7 с дашбордом). Пока
  один свод.

## Что НЕ входит

- Визуальный review (Storybook + vision) — отложить до Phase 7 (UI).
- Playwright E2E — там же.
- Debug-агент (читает артефакты, предлагает правки) — далекое "потом",
  эвал-харнес появится в Phase 8.
- Эвал-харнес — Phase 8.

## Зависит от

Phase 5 (MCP, чтобы правила подтягивались динамически, а не из деплоя).

## Definition of Done

Заполняется в `soly plan 6`. Ожидаемые проверки:

- Воркер пытается удалить падающий тест → хук блокирует, прогон падает,
  retry считается.
- Задача с `budget=0` отвергается до запуска контейнера.
- 3 фейла подряд на дешёвой модели → 4-я попытка автоматически уходит на
  ведущую.
- Cost-per-successful-task появляется в дашборде (даже если самого дашборда
  ещё нет — API endpoint готов).

## Hard constraints

- **Draconian analyzers — non-negotiable** (architecture.md §01). Ослабить
  "чтобы быстрее собиралось" = выбить главную опору качества.
- **Хук запрещает править тест-файлы**, если задача не "написать тесты".
  Приёмочные тесты на критичных путях — пишутся человеком, не агентом.
- **Эскалация — явный path**, не "может быть, разберёмся".
- **Решение "откатить / изменить" принимает человек** (architecture.md §01:
  авто-самоизменений нет).

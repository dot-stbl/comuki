# Правила фронтенда и визуального тестирования

> Стек: **React 19 + Vite + собственный кит (`@/shared/ui`) + CSS Modules на
> токенах + Storybook**.
> Цель: качественный структурный UI без «нейрослопа». Любой UI-компонент
> проходит три слоя: **(1) ограничения до генерации → (2) детерминированные
> тесты → (3) цикл визуальной критики со скриншотами.**
>
> Это не пожелания, а правила. Нарушение пунктов из раздела «Жёсткие
> ограничения» = ошибка, которую нужно исправить, а не обсуждать.

**Авторитет по визуальному миру — [`DESIGN.md`](../../../DESIGN.md) в корне
репозитория**, по киту — [`dashboard/src/shared/ui/AGENTS.md`](../../../dashboard/src/shared/ui/AGENTS.md).
Этот файл — процесс сборки; когда он расходится с ними, выигрывают они.
`.agents/docs/design-system/` описывает **прежний** мир и годится только как
история.

---

## 0. Главный принцип

Ты **не видишь вёрстку по коду**. «Кривой отступ», «поехавшая сетка»,
«элементы не выровнены» нельзя поймать чтением JSX/CSS — только глядя на
отрендеренный результат.

Из этого следует разделение обязанностей, и оно жёсткое:

- **Агентская сессия не запускает Storybook, playwright и chromium** — это
  long-lived процессы, запрет из `AGENTS.md` §6, он убивает рантайм харнесса.
  Агент отвечает за детерминированный слой: типы, тесты, линт, истории на
  каждое состояние, соблюдение шкал и токенов по разделу 1.
- **Скриншот-цикл (раздел 5) — контур человека.** Он обязателен перед тем,
  как компонент считается готовым, но исполняет его тот, у кого запущен
  dev-сервер.

«Выглядит хорошо» без скриншота — по-прежнему запрещённый ответ. Просто
произносит его не агент, а человек, и агент не имеет права заявить
«готово» — он заявляет «детерминированный слой зелёный, нужен визуальный
проход».

## 1. Жёсткие ограничения (источник слопа — свобода, лишаем её)

### Spacing и сетка
- Базовая сетка — **4px** (шкала 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64).
  Все отступы кратны 4. Предпочитать кратность 8 для крупных блоков.
- Отступы задаются **в CSS Module через шаговые токены**, не числом в JSX.
  Если нужного шага нет в шкале — значит макет неверен или нужен новый токен
  в `app/styles/tokens.css`, а не пиксель в компоненте.
- Layout строится через `flex`/`grid` + `gap`. **Не** разносить отступы
  марджинами на дочерних элементах вразнобой.
- Не смешивать способы задания одного отступа (либо `gap` на контейнере,
  либо margin на детях, не оба).

### Токены и стили
- Цвета, радиусы, тени, типографика — **только `var(--token)`**.
  **Голый hex, голый px и голый font-family в CSS Module запрещены.**
  Нет токена — добавь его в `tokens.css`; если это цвет, он принадлежит теме
  в `app/theme/themes.ts`, а не компоненту.
- Радиусы — из четырёхшаговой шкалы, один язык скруглений на компонент.
  `--r-pill` — легаси, к нему не тянуться.
- Глубина — три плоскости и не больше: Lift, Header, Modal. Focus ring — не тень.
- Статус несёт **и цвет, и переплёт** (`data-status`), чтобы читаться в
  монохроме. Цветная точка как носитель смысла запрещена — устройство
  выведено из обращения.

### Компоненты
- Сначала **переиспользовать примитивы кита** из `@/shared/ui` (`Button`,
  `Section`, `Select`, `Tooltip`, `ConfirmDialog`, `BottomSheet`, `SplitPane`,
  `DataTable`, `StatusBadge`, форменное семейство `Field`/`TextField`/
  `ChoiceField`/`SelectField`/`SwitchField`/`NumberField`/`TextareaField`,
  `Notice`, `CopyButton`, `FormDialog`). Свой компонент — только если в ките
  аналога нет.
- **UI-библиотеку не подключать.** shadcn/ui вырезан целиком (175 файлов,
  14 зависимостей), вместе с ним recharts. Кит — единственный источник
  примитивов. Это решение владельца, а не временное состояние.
- **`cva` не использовать.** Варианты — обычные пропсы плюс `data-*`
  атрибуты, стили к ним в CSS Module. `clsx`/`tailwind-merge` остаются
  доступны для склейки классов, но не как система вариантов.
- Новый компонент кита — **триада**: `.tsx` + `.module.css` + `.stories.tsx`,
  экспорт через баррель `@/shared/ui`. Составной примитив (таблица с
  тулбаром, пейн-группа с сепаратором) — своя папка с `index.ts`.
- Доступность и поведение сложных контролов — из `react-aria-components`,
  а не руками. Это библиотека поведения, не UI-кит; запрет выше её не касается.
- Семантика: интерактив — это `<button>`/`<a>`, а не `<div onClick>`.
  Каждое поле формы имеет `<label>`. Изображения имеют `alt`.
- Скрывать по разрешениям, а не отключать: отказ по праву рендерится
  присутствующим контролом с `aria-disabled` и причиной, а не `disabled`.

### Типографика и иерархия
- Два голоса, не смешивать: **Archivo** несёт смысл (заголовки, проза),
  **JetBrains Mono** — значения (числа, идентификаторы, данные). Цифр в
  Archivo не бывает, предложений в моно — тоже.
- Размеры — из шкалы темы, не произвольные. Видимая иерархия: заголовок /
  подзаголовок / тело различимы по размеру и весу. «Всё одного размера» — слоп.
- Ширина текстовых колонок ограничена (52ch там, где текст идёт абзацем).
- Табличные цифры (`tabular-nums`) для всего, что стоит в колонке или
  обновляется на месте.

### Tailwind
В сборке он ещё присутствует (`@import "tailwindcss"` в `index.css`, плагин в
`vite.config.ts`), но **утилит в `dashboard/src` ноль**, и добавлять их не надо.
Нужен стиль — он идёт в CSS Module на токенах. Мост-имена в `tokens.css`
(`--card-foreground`, `--muted` и подобные) — остатки, на новых поверхностях
их не использовать.

## 2. Конвенции историй Storybook

Каждый компонент сопровождается историями — это и тестовая поверхность,
и то, что человек будет скриншотить.

- Стори на **каждое значимое состояние**: `Default`, `Loading`, `Disabled`,
  `Error`, `Empty`, `WithLongText` (переполнение!), и крайние случаи.
- Использовать `args` + `argTypes`, включить `autodocs`.
- Состояния не «прятать» — каждое отдельной историей, чтобы каждое можно
  было снять и проверить.
- Поведение (клики, фокус, ввод) покрывать `play`-функциями.

Изолированный URL истории для скриншота (без хрома Storybook):

```
http://localhost:17010/iframe.html?id=<story-id>&viewMode=story
```

Порт **17010** — из пула 17000–17200 (`process/ports.md`), он зафиксирован в
скрипте `storybook`. Случайные порты запрещены.

## 3. Что гоняется на самом деле (CI-гейт)

Не путать с тем, что хотелось бы. На сегодня гейт — вот такой:

```bash
cd dashboard
bun run typecheck   # tsc -b
bun run lint        # eslint
bun run test        # vitest run, environment: jsdom
```

Покрытие — `bun run test:coverage`, пол **70% по строкам** (не 80+).

**Чего в гейте нет и почему — не «чинить» самовольно:**

| Хотелось | Состояние |
|---|---|
| `@storybook/addon-a11y` (axe) | Отключён намеренно. `TODO(phase-7)` в `.storybook/main.ts`: ждёт Storybook 10, проект на SB 8 |
| `@storybook/addon-vitest` (browser-mode component-тесты) | Отключён намеренно. `TODO(phase-7)`: ждёт совместимости с Node.js 24 ESM |
| Визуальная регрессия (Chromatic / `storybook-addon-vis`) | Не подключена |
| eslint-запрет arbitrary-значений | Не настроен; раздел 1 держится ревью, а не линтом |

Это записанные решения с причинами. Агент, который «поможет» и поставит
addon-a11y, откатывает чужое решение и ломает сборку Storybook. Хочешь
поменять — это отдельное изменение с обоснованием, а не побочный эффект.

> Этот слой ловит регрессии и объективные дефекты, но **не отвечает**, хорош ли
> сам дизайн. За это отвечает раздел 5.

## 4. Дополнительные проверки, доступные агенту

Дёшево, детерминированно, без long-lived процессов:

- `responsive.test.ts` держит весь `src/app` и `src/shared` под
  `prefers-reduced-motion` — новая анимация обязана пройти под ту же охрану.
- `app/theme/theme-css.test.ts` и `app/theme/palette.test.ts` держат реестр
  тем и палитру — новая тема обязана объявить весь набор примитивов, а не
  половину. Голый hex в CSS Module — повод для правки, а не для нового
  токена «по-быстрому».
- `bun run audit:fe` (`scripts/rule-audit.ts`) печатает корпус правил. Он
  **warning-only**: пропуск — это пропуск гейта загрузки, а не мелкая
  небрежность.

## 5. Цикл визуальной критики (контур человека)

Обязателен перед «готово». Исполняет человек с запущенным dev-сервером;
агент к этому разделу готовит материал (истории на все состояния) и
принимает по нему правки.

Инструмент: браузер, при наличии — Playwright MCP (`browser_navigate`,
`browser_resize`, `browser_take_screenshot`, чтение DOM / `getComputedStyle`).

### Процедура для каждого компонента
1. Запустить Storybook, открыть изолированный iframe истории.
2. Снять скриншот в **трёх вьюпортах**: `375` (mobile), `768` (tablet),
   `1440` (desktop). Сетка и layout ломаются именно на брейкпоинтах.
3. Пройти **полностью** по рубрике ниже, по каждому пункту.
4. Выписать **конкретные дефекты**: какой элемент, что не так, какое
   значение должно быть. Не «выглядит неаккуратно», а
   *«у `.cardHeader` `margin-left: 13px` — нет в шкале 4px, должно быть 12px»*.
5. Исправить → переснять → повторять, пока рубрика не чистая.

### Рубрика (проходить по каждому пункту, не пропускать)
1. **Сетка**: все отступы кратны 4 (предпочтительно 8)? Нет «почти-значений»?
2. **Ритм отступов**: расстояния консистентны? Нет соседних `16px` и `20px`
   без причины?
3. **Выравнивание**: элементы выровнены по краям/осям? Оптическое
   выравнивание соблюдено (иконка+текст, числа в таблице)?
4. **Радиусы/тени/типографика**: один язык на весь компонент, всё из токенов?
5. **Переполнение**: длинный текст не ломает layout, нет обрезки, нет
   горизонтального скролла на 375px?
6. **Иерархия и плотность**: видна структура (заголовок/тело/действия)?
   Не «всё одинаковое»? Не слишком плотно/разреженно?
7. **Контраст**: текст читаем на фоне? Статус читается в монохроме?
8. **Состояния**: hover/focus/active/disabled/loading выглядят корректно и
   отличимы?
9. **Адаптив**: на 375 / 768 / 1440 ничего не сломано, контент перетекает
   логично?
10. **Обе темы**: светлое и тёмное прочтение выбранной темы одинаково
    выверены? Ни один цвет не определён только в одной из них?

### Подтверждать глазомер цифрами (ключевой приём)
Скриншот говорит «криво», но это субъективно. По подозрительным элементам
**читать `getComputedStyle`** и сверять с разрешённой шкалой. Тогда дефект
становится объективным и сразу чинится:

> `getComputedStyle($0).marginLeft === "13px"` → не на шкале (4/8/12/16…)
> → исправить на шаговый токен (12px).

Эвристика по стоимости: **структуру** (что во что вложено, какие computed-стили)
проверять по DOM/accessibility-дереву — дёшево и точно; **скриншоты** — для
финального «гештальт-взгляда» и брейкпоинтов, не на каждое мелкое изменение.

### Если есть макет
Экспортировать таргет-скриншот, считать pixel-diff (pixelmatch + pngjs) между
текущим состоянием и целью, править UI в сторону макета по diff-картинке.

## 6. Definition of Done для UI-компонента

**Агентская половина** — без неё нельзя отдавать на просмотр:
- [ ] Использованы примитивы кита там, где возможно; своего компонента нет
      там, где есть готовый.
- [ ] Триада на месте: `.tsx` + `.module.css` + `.stories.tsx`, экспорт из
      `@/shared/ui` (для кит-компонентов).
- [ ] Ноль голых hex / px / font-family в CSS Module; всё на токенах.
- [ ] Истории на все значимые состояния, включая `WithLongText`.
- [ ] `bun run typecheck && bun run lint && bun run test` — зелено.
- [ ] Новая анимация под `prefers-reduced-motion` и оправдана как **момент**
      (вход или изменение), а не как фоновое украшение.

**Человеческая половина** — после неё компонент готов:
- [ ] Пройден цикл визуальной критики в 3 вьюпортах, рубрика чистая,
      подозрительные отступы подтверждены через `getComputedStyle`.
- [ ] Проверены оба прочтения темы.

## 7. Анти-паттерны (это слоп — не делать)

- Голый `13px`, `#3b82f6`, `font-family: Inter` в CSS Module — мимо токенов.
- Подключение UI-библиотеки, возврат shadcn, `cva` как система вариантов.
- Свой компонент там, где есть примитив кита.
- `<div onClick>` вместо `<button>`; поля без `<label>`.
- `disabled` как способ показать отказ по праву.
- Цветная точка как носитель статуса; статус без переплёта.
- Цифры в Archivo, предложения в JetBrains Mono.
- Разнобой отступов марджинами вместо `gap`.
- «Всё одного размера», отсутствие иерархии.
- Цвет, определённый только внутри одного прочтения темы.
- Запуск Storybook / playwright / dev-сервера **из агентской сессии**.
- Установка addon-a11y или addon-vitest «заодно» — они отключены осознанно
  (раздел 3).
- Ответ «выглядит хорошо» без скриншота и без прохода по рубрике.

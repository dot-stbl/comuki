## Краткая суть Comuki

Платформа, где **ведущая модель** (мозг) декомпозирует задачу и дирижирует роем **рабочих моделей** (эфемерные воркеры в контейнерах), которые пишут / тестируют / готовят к выкату фичи. Общая база знаний и правила по MCP. Защита от слопа — проверенные скиллы-рецепты + жёсткие анализаторы + дизайн-система как принуждаемое правило.

**Стек:** платформа на C#/.NET (orchestrator, proxy на YARP, mcp, Translator на AOT). Агенты на TS: pi для воркеров (контроль/наблюдаемость), форк GSD под Claude Code для разрабов (UX) — оба правил не хранят, берут из единого свода. Дашборд React+shadcn. Хранилища: Postgres (состояние+очередь+вектора), MinIO (артефакты), Nexus (пакеты). Швы: gRPC (Translator↔оркестратор), MCP (агент↔знания), SignalR (дашборд). Наблюдаемость: OpenTelemetry + Victoria. Всё self-hosted.

**Фаза:** MVP — человек в петле, задачи ставятся руками, выкат в прод вручную. Полная автономия — отложена.

## Следующий шаг

Первый код — контракт «ведущая модель ↔ оркестратор» (четыре типа решений: план / бриф / вердикт / эскалация, валидируемые схемы). Дом — `comuki-orchestrator`. JSON Schema как единый источник типов для C# и TS, чтобы контракт не разъехался между платформой и плагином.

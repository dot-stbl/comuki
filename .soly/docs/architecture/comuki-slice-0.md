# Comuki — Slice 0: первый вертикальный срез

Цель: **один тикет проходит сквозь систему через одного воркера от начала до конца.**
Тонкий срез через все слои, чтобы проверить три бумажных решения на реальности:
**pull-модель**, **Translator/gRPC**, **пригодность pi**.

Не «построить Comuki» — а доказать, что фундамент дышит. Качество, слоп, стадии,
знания — всё потом.

---

## Принцип среза

Режем сквозь все слои, но тонко. И **риск-первым**: сначала то, что на бумаге,
но ни разу не потрогано руками. Порядок шагов — от самого неизвестного к самому
понятному, чтобы плохую новость узнать в первый час, а не на пятый день.

Самое непроверенное — **pi** (выбран по обзору, не по опыту). Поэтому шаг 0 — он.

---

## Шаги (каждый что-то де-рискует)

### Шаг 0 — Проверить pi в одиночку (≈1 час, до любой инфры)

Запустить pi headless вручную, с тривиальным промптом, вывод в stream-json.
Убедиться: запускается неинтерактивно, выдаёт парсимый поток событий, ходит к
модели (пока с твоим прямым ключом).

**Проверяет:** что pi вообще ведёт себя так, как мы предположили. Если нет —
узнаёшь СЕЙЧАС, до того как построил вокруг него Translator и контейнеры.
Это самый дешёвый способ убить или подтвердить главное допущение.

> Если pi не подойдёт — здесь же быстро проверить тот же сценарий на Claude Code
> headless (`claude -p`). Развилка агента воркеров решается тут, на живом, а не
> на бумаге.

### Шаг 1 — Postgres + claim (pull-примитив)

Таблица `tasks`. Крошечная консоль вставляет задачу. Другая — клеймит через
`FOR UPDATE SKIP LOCKED` + ставит lease. Запустить два клеймера разом.

**Проверяет:** pull-модель. Два воркера не берут одну задачу; протухший lease
возвращает задачу в пул. Ничего больше — ни DAG, ни стадий.

### Шаг 2 — Translator запускает pi и парсит вывод (без gRPC)

Translator (C# AOT) делает `Process.Start(pi)`, читает stream-json построчно,
парсит в типизированные события (`StageReport`, `StageActivity`), печатает их.

**Проверяет:** мост парсит сырой поток pi в наши типы. Стабильно ли, не рвётся ли.

### Шаг 3 — gRPC между Translator и оркестратором

Соединить: Translator стримит события оркестратору по gRPC (bi-di); оркестратор
умеет прислать `Stop`.

**Проверяет:** двунаправленный типизированный канал. Оркестратор видит поток в
реальном времени и может вмешаться.

### Шаг 4 — Собрать в контейнере, замкнуть цикл

`worker.Dockerfile` = pi + Translator. Оркестратор: вставил задачу → поднял
контейнер → Translator (внутри) клеймит задачу, запускает pi на тривиальном
брифе → стримит события назад → оркестратор логирует финальный `StageReport` →
контейнер умирает → lease освобождён.

**Проверяет:** полный цикл вживую. Три бумажных решения подтверждены одним
прогоном.

## Что СОЗНАТЕЛЬНО заглушено в Slice 0

Не строим — добавляем в следующих срезах:

| Заглушено | Почему можно | Когда добавить |
|---|---|---|
| **Прокси** (pi бьёт в модель прямым ключом) | Loop доказывается и без него. Временный shortcut, НЕ в прод. | Slice 1 — виртуальные ключи |
| **Knowledge / MCP** | Тривиальный бриф знаний не требует | Slice 2 |
| **Правила / хуки** | Один тикет, слоп не проверяем | Slice 3 |
| **DAG, стадии, contract-first, фронт/бек** | Одна задача = одна стадия | позже |
| **Гейт верификации** | Просто ловим результат, не судим | Slice 3 |
| **Dashboard** | Смотрим в логи / БД напрямую | позже |
| **Реальный worktree** | Тривиальный репозиторий | при первой настоящей фиче |
| **MinIO / Nexus / Victoria** | Не нужны для loop | по мере надобности |
| **Reaper протухших lease** | Базовый claim сначала; reaper — поверх | сразу после шага 1 |

## Definition of Done

Запускаешь одну команду →
задача попадает в Postgres →
поднимается контейнер →
pi делает тривиальное изменение кода (напр. создаёт файл с заданным содержимым) →
оркестратор видит структурное событие «готово» с результатом →
контейнер умирает, lease освобождён →
**ты наблюдал весь путь в логах.**

Если это работает — фундамент Comuki реален, и дальше идёт наращивание, а не
проверка гипотез.

---

## Что срез проверяет, а что НЕТ

**Проверяет:** pull-модель работает; Translator мостит pi↔оркестратор; pi
управляем headless; gRPC несёт события; контейнер-воркер живёт полный цикл.

**НЕ проверяет (и не должен):** качество вывода агента, защиту от слопа,
многостадийность, знания, стоимость, наблюдаемость-как-продукт. Это не провал
среза — это его границы. Каждое — отдельный следующий срез.

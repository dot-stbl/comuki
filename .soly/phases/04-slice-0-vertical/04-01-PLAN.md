# Plan 04-01 — Phase 4 prep + sanity-check pi headless

## Goal

Подготовить фундамент для Phase 4 (Slice 0 Vertical Slice) и провести
первый де-рискинг шаг: убедиться что `pi` запускается headless в контейнере,
выдаёт парсимый stream-json, ходит к Anthropic-совместимому endpoint. Это
**step 0** из `.soly/docs/architecture/comuki-slice-0.md` — самый дешёвый
способ убить или подтвердить главное допущение.

После завершения:

- Phase 3 wrap-up закоммичен на `preparation/design-system` и замержен в
  `develop` (housekeeping — см. раздел «Pre-flight»)
- Ветка `preparation/translator-001` создана от `develop` (паттерн
  `preparation/<topic>-<NNN>`)
- `deploy/worker.Dockerfile` — реальный минимальный образ (не sentinel)
- `deploy/docker-compose.yml` поднимает 5 платформенных сервисов
- Worker-профиль в compose умеет билдить worker image одной командой
- `Comuki.Platform.Translator` — скелет C# worker-проекта (Sdk.Worker,
  **не AOT**) с интерфейсами, gRPC-контрактом, парсером stream-json и
  unit-тестами на записанных фикстурах
- `deploy/scripts/test-pi-headless.{sh,ps1}` запускает контейнер,
  парсит stream-json, валидирует что есть хотя бы одно событие
  правильной формы
- `dotnet build comuki.slnx` зелёный, Translator-проект в graph
- 1-2 `[hybrid]` коммита на `preparation/translator-001`

## Why now

Phase 3 завершена (дизайн-система + тест-инфра, 3.1/3.2/3.3 done). Phase 4
= первый runtime. Без Translator-проекта и работающего worker-образа планы
04-02..04-05 не имеют точки монтажа. Step 0 — самый дешёвый сигнал: если
`pi` в контейнере не выдаёт нормальный stream-json, узнаём сейчас, до того
как Translator и gRPC написаны.

0. **Pre-flight** (housekeeping, выполняется до этого плана — на момент
   старта плана уже должно быть готово):
   - `preparation/design-system`: 57 осмысленных изменений (dashboard
     polish, 3 новых компонента, plan-файлы, design-system docs,
     `.gitignore` обновлён для dashboard debris) одним коммитом
     `[hybrid] chore(phase-3): wrap-up — dashboard polish, design system
     docs, plan files, gitignore build artifacts`
   - Создать `develop` от `main`: `git branch develop main`
   - Merge `preparation/design-system` → `develop` (`--no-ff`, merge
     commit чтобы сохранить feature-branch историю)
   - `preparation/design-system` НЕ удаляем (legacy, в новом паттерне
     не используется)

1. **Создать ветку** `preparation/translator-001` от `develop`:
   ```bash
   git checkout develop
   git checkout -b preparation/translator-001
   ```

2. **Заменить `deploy/worker.Dockerfile`** (sentinel `FROM scratch` → реальный
   минимальный образ). Multi-stage не нужен — Translator в этом плане не
   собирается (это 04-03). Достаточно:
   - `FROM oven/bun:1.3.10-bookworm-slim` (bun уже встроен в base)
   - `bun add -g @earendil-works/pi-coding-agent` (правильное имя — sentinel
     ошибочно использовал несуществующий `@pi-coding/agent`)
   - `ENTRYPOINT ["pi"]` с дефолтным промптом через `CMD` (переопределяется
     в compose/env)
   - `WORKDIR /work`, `VOLUME /work` (для будущего worktree mount в 04-05)
   - `LABEL comuki.worker.phase="4-prep"` (вместо старого
     `phase-3-skeleton-not-yet-implemented`)

3. **Добавить worker-сервис в `deploy/docker-compose.yml`** с профилем
   (не стартует по умолчанию, активируется `--profile worker`):
   ```yaml
   worker:
     profiles: ["worker"]
     build:
       context: ..
       dockerfile: deploy/worker.Dockerfile
     image: comuki/worker:dev
     environment:
       ANTHROPIC_API_KEY: ${ANTHROPIC_API_KEY:-}
       ANTHROPIC_BASE_URL: ${ANTHROPIC_BASE_URL:-}
       PI_TEST_PROMPT: ${PI_TEST_PROMPT:-Say hello in exactly one word}
     networks: [comuki-net]
   ```

4. **Расширить `deploy/.env.example`** (placeholder-ы для реальных секретов
   в `.env`, который gitignored):
   ```bash
   # Phase 4 — worker image (passed through to pi in container)
   # Copy to .env and fill in for the headless test run.
   ANTHROPIC_API_KEY=
   ANTHROPIC_BASE_URL=
   PI_TEST_PROMPT=Say hello in exactly one word
   ```

5. **Создать Translator-проект** `platform/src/feature/Comuki.Platform.Translator/`:
   ```bash
   dotnet new worker -n Comuki.Platform.Translator \
     -o platform/src/feature/Comuki.Platform.Translator
   ```
   - Минимальные правки csproj: `TargetFramework=net10.0` (уже в
     `Directory.Build.props`), `RootNamespace`, `AssemblyName`
   - **НЕ** включать `<PublishAot>true</PublishAot>` (решение отложено —
     см. DECISION ниже)
   - **Добавить в `comuki.slnx`** через прямую правку XML (как в Phase 3 —
     `--solution-folder` на .NET SDK 10 Windows глючит), под
     `/platform/src/feature/` solution folder

6. **Скелет Translator-проекта** — базовая структура без реальной
   бизнес-логики (Process.Start(pi) — это 04-03):
   ```
   Comuki.Platform.Translator/
   ├── Program.cs                          (стандартный от worker-template)
   ├── Worker.cs                           (пустой BackgroundService stub)
   ├── Interfaces/
   │   ├── ITranslator.cs                  (marker, наполняется в 04-03)
   │   └── IPiRunner.cs                    (абстракция над Process.Start(pi))
   ├── Services/
   │   ├── PiEvent.cs                      (типы: StageReport, StageActivity)
   │   └── StreamJsonParser.cs             (чистый парсер, без IO)
   ├── Proto/
   │   └── translator.proto                (gRPC stub для 04-04)
   └── Comuki.Platform.Translator.csproj
   ```

7. **Unit-тесты парсера** `tests/Comuki.Platform.Translator.Unit.StreamJson/`:
   - xUnit v3 + Shouldly (как в Phase 3, MTP runner)
   - 4-5 фикстур в `tests/.../Fixtures/*.json` с примерами pi stream-json
     (нагенерим руками по фактическому формату вывода pi — уточнить
     во время исполнения через `--help` или эксперимент)
   - Тесты: парсер разбирает каждую фикстуру в `PiEvent`, не падает на
     unknown types, агрегирует в `StageReport` правильно
   - Покрытие 70% (gated, как везде)

8. **Test script** `deploy/scripts/test-pi-headless.sh` (POSIX) и
   `deploy/scripts/test-pi-headless.ps1` (PowerShell для Windows):
   - `podman compose --env-file deploy/.env --profile worker build worker`
   - `podman compose --env-file deploy/.env --profile worker run --rm worker \
       pi -p "$PI_TEST_PROMPT" --output-format stream-json` (или
       `podman run` напрямую)
   - Захватить stdout, грепнуть `^{"type":` (хотя бы одно событие)
   - Exit 0 если нашли, exit 1 с подсказкой если нет

9. **Validate docker stack** в worktree:
   - `cd deploy && podman compose --env-file .env up -d`
   - Дождаться healthchecks (5 сервисов)
   - `podman compose ps` — все healthy
   - `podman compose down` (без `-v` — volumes оставляем)

10. **Обновить `deploy/README.md`**:
    - Раздел "Worker image" — больше не sentinel, реальный минимальный
    - Раздел "Worker profile" — как билдить и запускать
    - Test script usage

11. **Логирование решений** в `.soly/STATE.md` через `soly_log_decision`:

      multi-stage (Translator собирается в 04-03)"

12. **Коммит** в ветке, 1-2 `[hybrid]` коммита на `preparation/translator-001`:

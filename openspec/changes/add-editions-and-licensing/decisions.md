# Editions and licensing — user decisions (grilling, 2026-09-25)

E1  Open-core. One codebase, one binary. Edition is a **runtime** capability gate, not a separate build, package, or feature flag. The same `comuki` artifact runs Community today and runs any paid tier tomorrow once a license is mounted — never two release pipelines, never two SKUs.
E2  Edition model. `Community` is the default (rank 0, no license required). One or more paid tiers live on top; a tier is identified by an open string code (not a fixed `pro` / `enterprise` enum) plus an ordinal rank so a third or fourth tier can be added without a schema change. The license carries the tier code and a list of seat / limit numbers; the registry declares the floor (every paid feature key has a minimum rank).
E3  Capability registry is one file, one source of truth. A stable `feature key` (dot.case, `resource:action` shape, same well-formedness rule as `PermissionKey` at `platform/src/modules/Identity/Comuki.Modules.Identity.Domain/Permissions/PermissionKey.cs:22`) maps to its minimum required tier rank. The registry is enumerated to drive a generated Markdown capability table at `openspec/specs/editions/capability-matrix.md` and a generated TypeScript contract — never a hand-maintained second copy of the table.
E4  License format is a compact two-part token `base64url(payload-json).base64url(ed25519-signature)`. Deliberately simpler than a JWT: one fixed algorithm, no `alg` negotiation surface to attack. `payload-json` carries `org` (licensee), `edition` (tier code), `seats` / `limits` (open number map keyed by limit name), `expiry` (ISO-8601 UTC), `features` (either an explicit feature-key allowlist **or** "all at or below my tier rank" — see E4a), and the public key is embedded in the binary (assembly-embedded constant or `.resource`, never configuration) so a customer can never supply their own "public key" and self-sign. Verification is 100% offline: signature check + expiry check against the local clock. **No phone-home, ever.**
E4a  Two license shapes are supported, opt-in per license: (a) explicit feature-key allowlist — a customer paid for an unusual feature set the tier rank would not normally cover; (b) implicit "all features at or below my tier rank" — the simpler, common case. The license carries a discriminator flag; the platform honours whichever the license declares and rejects the other as a malformed license (404 `edition.feature_unavailable`, never silent). Recommend **(b) implicit-by-rank** as the default issuance policy; **(a) allowlist** is the escape hatch for enterprise deals.
E5  License storage. Bound through `Host:License:Path` in `config.toml`; the value is resolved via the existing `ISecretResolver` (`platform/src/shared/Comuki.Shared.Kernel/Secrets/ISecretResolver.cs`) and the `SecretRef` machinery (`env:` / `file:` / `vault:` / `consul:` schemes — `platform/src/shared/Comuki.Shared.Kernel/Secrets/SecretRef.cs`). A malformed license fails loudly at boot (matches the "present-but-broken fails loud, absent behaves as Community" rule from `platform/src/shared/Comuki.Shared.Bootstrap/Config/Toml/ComukiTomlConfiguration.cs:14`); an absent license behaves as Community. Hot-reload via `IOptionsMonitor<LicenseOptions>` so a replaced license file is picked up without restart — required specifically because a license can change mid-process-lifetime (expiry, renewal, downgrade) and we want the gate to follow without an outage.
E6  Four enforcement points, all four required: (1) **host API** — `[RequiresFeature]` / `.RequireFeature()` / `[EnforceLimit]` on endpoints, gate before the handler runs; (2) **module installers** — `AddComukiModule<TModule>` refuses to wire a module whose class-level `[EditionFeature]` is not covered, logging (never silently no-op-ing) when a module is skipped; (3) **background workers** — `[RequiresFeature]` on an `IComukiWorker` implementation is checked by `ComukiWorkerRegistry` before the worker is registered / started (a license can expire mid-process-lifetime; a worker never starts but should not keep being skipped silently); (4) **dashboard / CLI feature visibility** — `GET /api/v1/edition` returns the current tier, license status (`valid` / `grace` / `expired` / `absent`), and the set of feature keys visible at the caller's tier, so the UI / CLI hide / upsell without hand-copying the registry.
E7  Behaviour when a paid feature is invoked without a covering license: HTTP **403**, RFC 9457 problem-details, machine code **`edition.feature_unavailable`** (dot.case, matches every other error code in this repo — `ProviderExceptionHandler.ExceptionMapping.Map` at `platform/src/host/Comuki.Host/Errors/ProviderExceptionHandler.cs:72`), `detail` names the feature key and the minimum edition required (never leaks license internals), plus a UI-facing upsell affordance: the problem response extension carries enough (feature key + minimum tier) for the dashboard to render an upsell without a second call. Count-quota limits use a sibling code **`edition.limit_exceeded`** on the same path.
E8  Downgrade / expiry behaviour is **read-only degrade, no data loss, ever**. On expiry (after grace) or downgrade to a tier that no longer covers data the customer already owns (e.g. they used multi-project under a trial and drop to Community): paid-gated *write* paths return `edition.feature_unavailable`; paid-gated *read / export* paths for data the customer already owns keep working, at minimum for export, so nothing is stranded. Grace period: a configurable window (default candidate: 14 days) after expiry during which paid features keep working with a visible warning surfaced via `/api/v1/edition`'s `status: grace` field — softens clock-skew and renewal-latency false positives under the fully offline verification model.
E9  Developer ergonomics. The registry, API gates, DI gates and worker gates are attribute / DI-based wrappers over the plumbing above — never raw port calls scattered through handler bodies. Specifically: `Features` and `Limits` smart-typed static catalogs (built through `Feature.Define(...)` / `Limit.Define(...)` factories, not bare string constants); `[RequiresFeature]` and `[EnforceLimit]` attributes mirroring `RequiresPermissionAttribute` (`platform/src/modules/Identity/Comuki.Modules.Identity.Application/Permissions/RequiresPermissionAttribute.cs`); `AddComukiModule<TModule>` and `AddForEdition<TService>` DI helpers; `[RequiresFeature]` on `IComukiWorker` implementations (the *background hosted-service* worker abstraction — `platform/src/shared/Comuki.Shared.Bootstrap/Workers/IComukiWorker.cs` — **not** the ephemeral coding-agent worker from `worker-runtime`; the two are distinct and this change only ever names the hosted-service one); a generated TypeScript contract for the registry keys alongside the generated doc table.
E10 Tests for both editions. A **fixture license per edition** used across the test suite: `TestLicense.Community` (the absence fixture, asserting the platform still composes with no license at all) plus at least one paid-tier fixture (e.g. `TestLicense.With(Features.MultiRepo)`). All fixtures are signed with a **test-only** keypair — never the production embedded public key. Architecture tests assert: (a) every feature key gated anywhere in the codebase (endpoint attribute, module installer check, background-worker check) exists in the `Features` / `Limits` registry (the reverse direction the `Permissions.cs` invariant does **not** cover; see `platform/src/modules/Identity/Comuki.Modules.Identity.Domain/Permissions/Permissions.cs:8` for the parallel `permissions ↔ roles` invariant); (b) every paid registry entry has at least one gate (the other direction); (c) a Community-edition DI graph composes cleanly with `ValidateOnBuild`, extending `tests/unit/Comuki.Host.Unit.DiComposition/HostServiceProviderShould.cs:19` with a case that builds the full host service provider with a Community (absent) license and asserts it validates — the whole point of "one codebase, one binary" is that Community composes with zero paid services registered, not crash resolving one that assumed a license.

# Worker commit attribution — user decisions

These are the binding decisions this change specifies against. They are
recorded here so the workstreams (`tasks.md`) and the implementing
agents pick them up unchanged; this is **not** a place to revisit them
absent new info.

D1  Two-layer enforcement, not one. The deterministic workspace-prep hook (Layer 1) and the post-pi verify/fixup pass (Layer 2) are both required. Layer 1 reduces how often Layer 2 has to do real work; Layer 2 is the actual guarantee. The hook alone depends on agent cooperation (`git commit --no-verify` bypasses it); verify/fixup alone works but wasteful. Mirrors "LLM proposes — system disposes" (`openspec/config.yaml` `context:`). Single-layer "just ask the agent nicely in the brief" is insufficient.

D2  Verify/fixup uses `git commit --amend`, not `git rebase` and not "silently rewrite as a new commit." Amend preserves the tree (only identity and message change), so the agent's code is not disturbed. A rebase would re-apply the commit's tree (re-running any post-commit hooks or worktree state) and could mutate what the agent produced. Silently rewriting as a new commit loses the original SHA, which breaks any downstream tools that pinned it.

D3  PATCH-after-create, not PR-creation. Comuki does not call `POST /repos/.../pulls`; it appends the footer to a PR that already exists via `IPullRequestAnnotator`. Comuki has no PR-creation call today, and adding one is a larger surface than this change needs. The footer is the only required Comuki-side PR metadata; the agent or human opens the PR itself. This also matches the existing `MergeQueueEntry.PullRequestUrls` ingestion shape. The agent composing the footer in the PR body alone depends on cooperation — exactly what two-layer enforcement avoids.

D4  The human-attribution trailer is `Requested-by:`, not `Co-Authored-By:` and not `Signed-off-by:`. The no-AI-attribution gate's `WHOLE_LINE_PATTERNS` includes `^co-authored-by:.*?\b<vendor>`; spelling the trailer `Co-Authored-By:` would risk false positives on the gate if a future commit ever listed a vendor in the same message. Using a distinct name sidesteps that. `Signed-off-by:` is wrong semantic — DCO sign-off is a legal claim about contribution, not a provenance marker.

D5  The white-label toggle lives on `RepositoryPolicy` (R3, owned by `add-multi-repo-projects`'s `repositories` capability), not on a Project. The issue language says "Configured in the repository policy (R3)." Attribution is repository-scoped: a service repo and its docs repo may have different white-label settings under the same Project. A Project-scope toggle would force one policy across all attached repositories, contradicting R3's "rules belong to the repository, never duplicated per-Project" stance.

D6  Trailer order in the message trailer block: `Generated-by`, `Comuki-Run`, `Comuki-Mission` (when present), `Requested-by`. The order is fixed by this change (the hook script and Layer 2 assertion both use this order); it is not a free-form convention. Reading order matches the order in which the values are resolved by Translator: the version first (the most stable identifier), then the run id, then the mission id (when present), then the requester.

D7  Field-by-field resolution is normative, not implementation guidance.
- `Generated-by: Comuki vX.Y.Z` — `<X.Y.Z>` (and the `+sha` suffix when present) comes from `ComukiBuildInfo.Read()` reading the Translator's **own entry assembly's** `AssemblyInformationalVersionAttribute`. No env-var threading of the version.
- `Comuki-Run: <run-id>` — the `runId` from `StageStart` (worker-runtime spec: "`Start` (StageStart: workItemId, runId, brief)"). No new plumbing.
- `Comuki-Mission: <mission-id>` — **conditional**: emitted only when the run belongs to a Mission (post-Mission-epic). Omitted entirely (never blank, never `unknown`) in the no-Mission case. Conditional emission is named in `specs/commit-attribution/spec.md` as an explicit scenario.
- `Requested-by: <human>` — resolution table: intake-originated runs resolve to `IncomingTicket.Author` (`platform/src/modules/Intake/Comuki.Modules.Intake.Domain/Tickets/IncomingTicket.cs:40`, "Author login / display name on the source tracker"); chat/dashboard-originated runs resolve to the authenticated subject (the same shape `RequiresPermissionFilter.cs:57` uses for `context.HttpContext.User`); scheduled-job-originated runs resolve to the fixed literal `comuki-scheduler`. No single `Run` field carries this today — flagged in `design.md` Open Question 3 and `tasks.md` workstream 1 as a required plumbing step.

D8  The PR footer text is one line, blank-line preceded, exact text:
```
---
🤖 Generated by Comuki — run [link](<PublicUrl>/projects/<projectId>/runs/<runId>)
```
The link target is built from `AuthPublicHostOptions.PublicUrl` (`COMUKI_PUBLIC_HOST_URL`, the existing "operator-configured public base URL, never the inbound Host header" pattern). Reuse the existing option, do not invent a second "public URL" config. The 🤖 emoji is deliberately distinct from the no-AI-attribution gate's `^(?:🤖\s*)?generated with\b` pattern — the gate trips on the phrase "generated with" (linking the emoji to a vendor/tool by name), not on a bare emoji, so the footer survives the gate unchanged. This is verified by inspection against `WHOLE_LINE_PATTERNS` in `scripts/commit-lint.mjs`.

D9  The Layer 2 verify/fixup pass runs only when a source workspace exists for the run. Today no source workspace exists on `master` (`feature/source-workspace-clone` / `add-multi-repo-projects` have not merged — verified by grep). The pass is skipped entirely on runs with no source workspace, not an error. Same shape as `ProfilesProvider`'s existing "no profiles source configured → warn and skip" branch. When the source-workspace concept lands, both layers are required to fire.

D10  The attribution fixup pass does not itself fail an otherwise-successful work item. A commit that cannot be amended to satisfy the contract (rare edge case — `pre-commit` hook rejecting amend, worktree corruption, etc.) is logged and a `run.attribution_fixup_partial` journal event is emitted, but the run still completes. The reasoning: a worker can produce a fully correct code change whose only fault is one missing trailer; failing the item over that one trailer forces a retry that redoes the entire work. The warning surfaces the gap for review, the run still completes, a follow-up clean fixup or human amend can resolve the residue. This is recorded as `design.md` Open Question 4 (a future change may handle these edge cases; this change names them and moves on).

D11  The `IRepositoryBotIdentity` port's interim shape (until R4 lands) is a per-project `ProjectSettings.AttributionIdentityOverride?: string` with a module default of `{ name: "Comuki", email: "noreply@comuki.dev" }`. Per-project override is more honest about the gap than a global-only default — see `design.md` Open Question 1. When R4 ships, the interim implementation is replaced wholesale without changing Layer 1 / Layer 2 callers.

D12  The GitHub PR-annotation adapter uses Refit (not raw `HttpClient`, not Octokit.NET). Smallest delta from existing patterns; the bearer-token plumbing is already established for Intake's GitHub adapter — reuse the auth shape, add a new typed client interface (`IGitHubPullsClient`). See `design.md` Open Question 2.

D13  Coexistence with the no-AI-attribution gate is **verified by direct inspection**, not by adding an allowlist mechanism. `AI_VENDORS` does not contain `"comuki"` (the list is closed and vendor-shaped); none of the four Comuki trailers or the PR footer matches `WHOLE_LINE_PATTERNS` or `INLINE_PATTERNS`; the `Requested-by:` trailer is deliberately distinct from `Co-Authored-By:` for the same reason (D4). A pinned regression test in `scripts/commit-lint.test.mjs` asserts that `stripAttribution` leaves a message containing all four trailers byte-for-byte unchanged.

D14  `Layer 1` is a **sibling preparer**, not a modification of `ProfilesProvider.cs`. The Translator loop calls both preparers alongside each other — same "write a file into the workspace before pi starts" shape, separate code path, separate file. `platform/src/host/Comuki.Host.Translator/Attribution/Hooks/**` is the new folder; `ProfilesProvider.cs` is not edited.

D15  The Layer 2 verify/fixup pass inserts into the existing Translator loop between step 5 ("send the final StageReport") and step 7 ("else complete on success or fail"). Insertion between the existing steps is additive — no step is removed. The `worker-runtime/spec.md` delta spec records this as one new requirement, not as an edit to the existing "Translator loop" requirement's prose.

Constraints: this change is mostly greenfield — no `Repository`, `RepositoryCredentialRef`, `ProjectRepositoryAttachment`, `MissionId` on `Run`, or PR-creation call exists in `platform/src` today (verified by grep). The `editions` capability (sibling change `add-editions-and-licensing`, #164) is the producer of `Features.CommitAttributionWhiteLabel` and the `[RequiresFeature]`/`IEdition` gate; this change consumes by name only. The white-label toggle's spec section is conditional on that change landing; named in `tasks.md` workstream 5's `Deps:` line. Wave slot: after `feature/source-workspace-clone` (#125) and `add-multi-repo-projects` (#163) merge — Layer 1 / Layer 2 depend on a source workspace existing; until then, the change specifies against the future shape and the implementing workstreams stub against an interim resolver (D11).
